WHY I PICKED IT

A support inbox holds
more than individual complaints.

I wanted to connect AI to an ordinary business problem: messy customer messages that need to reach the right person. Several messages might also reveal a recurring packing, product or delivery issue.

I built Customer Support Hub around a fictional UK furniture store, Hearthwood Home. The business identity is a demo configuration. The software handles intake, suggestions, review and investigation.

The important boundary is between suggesting something and doing it. A route is not an assignment, a draft is not a sent email, and an approved reply is not a resolved complaint.

HOW IT WORKS

AI for extraction.
Rules for the boundaries.

I use the OpenAI Responses API for optional classification and screenshot transcription. The app checks the output structure and makes sure evidence quotes appear in the complaint text.

Local logic adds safety checks and creates reply drafts from controlled templates. Customer details are suggested from visible transcript text and confirmed before being applied. SQLite keeps the original suggestion, corrections and review history.

Gmail can connect through encrypted SMTP using an app password. Each message gets a saved preview and a single send attempt. An uncertain outcome is recorded for manual checking rather than retried automatically.

ONE FAILURE I KEEP VISIBLE

The offline detector missed a safety concern described as an item that “wobbles dangerously.” It marked the message unclear. That’s why the reviewer still needs to read the original complaint.

WHAT WENT WRONG

A polished answer
can still be the wrong one.

The earlier rules confused delayed refunds with late deliveries. I added regression cases and better handling for negation. Screenshot text initially stayed separate from customer fields, so a reply could still use the wrong name. I added source-backed suggestions and an explicit confirmation step.

I also ran into two local servers sharing a Windows port. Requests sometimes reached the old app. The fix uses exclusive port ownership and a clear version check.

The reports originally sounded too certain about causes. I changed them to show an observation, source complaints, a hypothesis and a sensible next investigation step.

WHAT I’M LEARNING

Evidence matters more
than a confident summary.

I’m learning to separate model output, application checks and human decisions. Structured JSON is useful, but it cannot prove a classification is right.

WHAT I’D IMPROVE NEXT

Clear ownership,
then a stronger pilot.

I would add authenticated staff accounts, named case owners and proper waiting/resolved/reopened states. I would also test fresh messages written by someone else and verify Gmail delivery with a controlled inbox.

Current scope

This is a single-device local demonstration. It does not include a live inbox connection, verified staff identities, automated refunds or production hosting. No handling-time savings or commercial outcomes have been measured.
